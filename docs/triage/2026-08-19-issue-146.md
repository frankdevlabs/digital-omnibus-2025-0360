## Assessment

**In scope and substantive.** Scope is unambiguous: the amendment PDF's own cover carries `2025/0360(COD)` /
`COM(2025)0837`, the correct joint committees and the correct draft report (PE786.818, Salla/Kaljurand) — the
**data/cyber** file, **not** the AI-Act file 2025/0359.

This is a **second confirmed part** of the same >1,762-amendment tabling already registered under
[`CJ72-AM-791883`](../../data/documents.yaml) (part = Am 1741–1840) via [triage #133](2026-07-29-issue-133.md).
Same cover date (27 Jul 2026), same `AM_Com_LegReport` multi-part set; this part covers **amendments 401–526**.
These are **competing** MEP amendments, **not** the rapporteurs' text and **not** an adopted committee line
(the joint vote is expected ~Q4 2026), so — as with #133 — they are **not** folded into the per-provision
comparison cells.

Per the upgrade rule this runs on the **parliament-text** playbook. Unlike #133, though, the **English**
operative text is **not retrievable** — only the German version exists so far. Transcribing/translating the
German amendments into the English extracts ourselves would **not be a faithful transcription** (the
`extracts/` layer is faithful transcription of the source, not translation), so **no per-provision claims are
made**. The German PDF *is* retrievable, so — unlike a cite-only WAF case — it is **committed as the source**
and the document is registered with metadata; `pending_operative_text` stays set for the **English**
transcription, which re-surfaces once `CJ72-AM-790968_EN.pdf` publishes.
